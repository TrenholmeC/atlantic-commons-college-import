# Atlantic Commons college import

> This code was generated by Claude. The initial version was created based off Q1042, Q1041, Q1040, and Q1039 on Atlantic Commons.
> Additional prompts fined tuned the output and clarified additional constraints.

> This project serves as a test demonstration of using LLM tools with Wikibase.

> All data sumbitted to Atlantic Commons is reviewed by humans.

Creates College / College Campus / College Building / College Address items
on the [Atlantic Commons](https://atlanticcommons.ca) Wikibase, modelled on
these four existing example items:

- `Q1042` Holland College (college)
- `Q1041` Summerside Waterfront Campus (campus)
- `Q1040` Summerside Waterfront Campus Building (building)
- `Q1039` 98 Water Street Summerside, PE (address)

## Schema

| Property | Label | On item | Value |
|---|---|---|---|
| P1  | instance of | college / campus / building / address | `Q1036` college, `Q1038` campus, `Q1034` building, `Q1032` address |
| P23 | has campus | college | campus item |
| P22 | building | campus | building item |
| P21 | address | building | address item |
| P17 | street number | address | string |
| P18 | street name | address | string |
| P16 | postal code | address | string |
| P19 | municipality | address | item (e.g. `Q546` Summerside) |
| P20 | province | address | item (e.g. `Q3` Prince Edward Island) |
| P15 | forward sortation area | address | item (e.g. `Q918` C1N) |

Municipality, province, and forward-sortation-area items are treated as
pre-existing reference data. The script looks them up by exact label match
(`wbsearchentities`) and fails with a clear error if one doesn't exist yet —
creating those is out of scope here. The forward sortation area label used
for the lookup is derived from the first three characters of the address's
postal code, not a separate input field.

## Setup

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
```

### Bot account permissions

The script logs in with a bot password and calls `wbsearchentities` (read),
`wbeditentity` (create items), and `wbcreateclaim` (add statements),
passing `bot=1` on every write. For this to work:

- The wiki account itself should be in the `bot` user group (a sysop adds
  this via `Special:UserRights`). This isn't strictly required to make
  edits, but without it the `bot=1` flag is silently ignored, edits aren't
  marked as bot edits, and you're more likely to hit normal per-user edit
  rate limits during a bulk import.
- When creating the bot password at `Special:BotPasswords`, grant it at
  least:
  - **Create, edit, and move pages** — needed for `wbeditentity` to create
    new College / Campus / Building / Address items.
  - **Edit existing pages** — needed for `wbcreateclaim` to add linking
    statements (has campus / building / address) to existing items.
  - **High-volume editing** — recommended; matches the script's `bot=1`
    writes and exempts the account from the standard edit rate limit.

  No admin/sysop grants are needed for the bot password itself — the
  script never merges, deletes, or redirects items, and it doesn't create
  the municipality/province/FSA reference items (see "Schema" above), only
  looks them up.

For small test runs, pass `--no-bot-flag` to skip the `bot=1` flag on
writes. This lets a regular logged-in account (username/password, no bot
password or `bot` group membership needed) run the script — useful for
trying it out against a handful of test items before setting up a real
bot account for a bulk import.

You need a bot password: on the wiki, go to [Special:BotPasswords](https://atlanticcommons.ca), create
one, then copy `.env.example` to `.env` and fill it in:

```bash
cp .env.example .env
```

```
WIKIBASE_USERNAME=YourUsername@your-bot-password-name
WIKIBASE_PASSWORD=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

`.env` is listed in `.gitignore`, so your credentials won't be committed.

## Input data

A JSON list of colleges; each college has a list of campuses, each campus a
list of buildings, each building an optional address. See
`example_data.json` (it reproduces the four existing Q1039-Q1042 items
verbatim, so only use it with `--dry-run` — running it for real would create
duplicates of items that already exist).

Set any `"qid"` field to an existing QID (e.g. `"Q1042"`) instead of `null`
to reuse an existing item — e.g. to add a new campus to an existing college,
put the college's real QID in `"qid"` and leave the new campus's `"qid"` as
`null`. Once `"qid"` is set, that item's other fields (`label`,
`description`, `street_number`, etc.) are only needed for creating a new
item, so they can be left out entirely. The script only adds a linking
statement (has campus / building / address) when at least one side of the
link was newly created in that run, so re-running against already-linked
existing items won't create duplicate statements.

## Usage

Preview without writing anything:

```bash
python3 import_colleges.py --data example_data.json --dry-run
```

Run for real, writing a summary of created/reused QIDs:

```bash
python3 import_colleges.py --data mydata.json --output result.json
```

Small test run with a regular (non-bot) account, without marking edits as
bot edits:

```bash
python3 import_colleges.py --data mydata.json --no-bot-flag
```
